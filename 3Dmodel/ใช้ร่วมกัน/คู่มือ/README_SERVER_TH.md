# NetCare FS-220 — Rack Server 2U

โมเดลเซิร์ฟเวอร์แร็กแนวนอนสำหรับ Network Life สร้างใน Blender 5.2
เตรียมใช้เป็นฮาร์ดแวร์ File Server และใช้ชิ้นส่วนแยกในเควสประกอบเครื่อง
เป็นอุปกรณ์สมมติที่ออกแบบใหม่ ไม่ใช่โมเดลหรือ CAD ของ Dell/Supermicro และยังไม่ถูกนำไปแทนโมเดลในฉาก Godot

## เปิดดูไฟล์

ทุกไฟล์อยู่ใต้ `D:\Game Network\NetLife3D\assets\3Dmodel`

- `blend/rack_server_2u.blend` — ไฟล์ต้นฉบับ เปิดมาพบเครื่องประกอบครบและปิดฝา
- `exports/rack_server_2u.glb` — โมเดลพร้อมวัสดุและชิ้นส่วนภายในที่แยก Node สำหรับ Godot
- `renders/rack_server_2u_hero.png` — ภาพมุมหน้าพร้อมฝาเครื่อง
- `renders/rack_server_2u_rear.png` — ภาพด้านหลังและพอร์ตต่าง ๆ
- `renders/rack_server_2u_interior.png` — ภายในเครื่องเมื่อซ่อนฝาบน
- `renders/rack_server_2u_ports_closeup.png` — ภาพขยายพอร์ต LAN สองช่อง
- `exports/rack_server_2u.validation.json` — ผลตรวจโครงสร้างไฟล์ขณะสร้าง
- `exports/rack_server_2u.roundtrip.json` — ผลตรวจนำ GLB กลับเข้า Blender และทดสอบชิ้นส่วน

หากต้องการดูภายในใน Blender ให้ซ่อนวัตถุ `Top_Lid` ใน Outliner
หากต้องการย้ายฝา ให้ย้าย parent `Lid_Remove` แทนการย้ายตัวถัง

## รูปแบบและรายละเอียด

- ตัวถังโลหะกลวง ขนาดออกแบบ 430 × 520 × 87.5 มม. ไม่รวมมือจับและส่วนยื่น
- มีหูยึดแร็ก ช่วงกว้าง 482.6 มม. พร้อมช่องยึดและมือจับ ไม่ใช่ Tower Server
- ฝาเครื่องแยกชิ้น มีสกรูและตัวล็อกฝา ช่องระบายอากาศเป็นช่องเปิดจริง
- ด้านหน้าเป็นถาด SSD สองถาด พร้อมฝาปิดช่องสำรองสองช่อง
- SSD จำลองแบบ SATA 2.5 นิ้ว ในถาดขนาดกว้าง มี adapter ต่อเข้าบอร์ด backplane
- ภายในมี motherboard, CPU พร้อม heatsink และพัดลมสี่ตัว จัดทิศทางลมจากหน้าไปหลัง
- มีช่อง DIMM สี่ช่อง โดยติด RAM สองแผงที่ A1 และ B1
- มี NIC แบบ low-profile PCIe แยกถอดได้ พร้อมช่อง LAN 1 และ LAN 2 ด้านหลัง แต่ละช่องมีหน้าสัมผัส 8 จุด
- พอร์ต USB-A สองช่อง และ VGA สำหรับคอนโซล แยกจากพอร์ตเครือข่าย
- มี PSU เพียงหนึ่งชุด พร้อมช่องรับไฟ AC IEC C14 และจุดอ้างอิงต่อสายไฟ
- ไม่มีแบตเตอรี่ ไม่มี UPS ในตัว และไม่ได้จำลอง PSU แบบ redundant
- ตัวเครื่องเริ่มต้นในสถานะปิด ไม่มีสายไฟต่ออยู่ ไฟ Power/Health/Drive/Link/Activity ทุกดวงปิด

ข้อความ 16 GB บนข้อมูล RAM, 480 GB บน SSD และ 400 W บน PSU เป็นสเปกสมมติของ asset สำหรับจัดฉาก ไม่ได้กำหนดประสิทธิภาพเกมหรือเปลี่ยนขอบเขตบทเรียน

## ชิ้นส่วนสำหรับมินิเกมประกอบเครื่อง

| Parent หรือ Node | หน้าที่ |
|---|---|
| `RackServer_FS220_2U` | root ของเซิร์ฟเวอร์ทั้งหมด |
| `Server_Chassis` | ตัวถัง หูยึดแร็ก รางถาดไดรฟ์ และ backplane ที่ติดตั้งไว้แล้ว |
| `Lid_Remove` → `Top_Lid` | ฝาบนแยกชิ้น |
| `RAM_A1`, `RAM_B1` | แผง RAM สองแผง แยกย้ายได้ |
| `Slot_RAM_A1/A2/B1/B2` | จุดอ้างอิงติดตั้ง RAM |
| `Drive_01_Carrier`, `Drive_02_Carrier` | ถาดไดรฟ์พร้อม SSD และไฟสถานะของแต่ละถาด |
| `Bay_03_Blank`, `Bay_04_Blank` | ฝาปิดช่องที่ไม่มีไดรฟ์ |
| `Slot_Storage_01` ถึง `Slot_Storage_04` | จุดอ้างอิงช่องไดรฟ์ |
| `NIC_PCIe_DualLAN` | การ์ด LAN พร้อม bracket พอร์ต ไฟ และป้ายที่เคลื่อนตามการ์ด |
| `Slot_NIC_PCIe` | จุดอ้างอิงตำแหน่งการ์ด |
| `Socket_RJ45_LAN1`, `Socket_RJ45_LAN2` | จุดวางหัวสายเครือข่าย |
| `PSU_Module` | ชุด PSU ปิดผนึก แยกถอดทั้งชุดได้ |
| `Slot_PSU`, `Socket_AC_Power` | ตำแหน่ง PSU และจุดต่อสายไฟ AC |
| `Motherboard_Fixed`, `CPU_Heatsink_Fixed`, `Cooling_Fan_Bank_Fixed` | ชิ้นส่วนที่ติดตั้งไว้ก่อนเริ่มเควส |
| `Internal_Harnesses_Fixed` | สายภายในจำลองที่ติดอยู่กับฝั่งตัวถัง |
| `LED_Power`, `LED_Health`, `LED_LAN1_Link` ฯลฯ | ไฟสถานะแยก mesh สำหรับเขียนระบบควบคุมภายหลัง |

ชิ้นส่วนทั้งหมดอยู่ใน GLB เดียว ไม่ต้องต่อไฟล์ texture ภายนอก
ชิ้นส่วนที่มี parent สำหรับถอดประกอบควรย้ายผ่าน parent นั้น เพื่อให้พอร์ต ไฟ และป้ายเคลื่อนตามกัน

## แกนและการเคลื่อนชิ้นส่วน

Blender ใช้ +Z ขึ้น และด้านหน้าเครื่องเป็น -Y
หลังส่งออก glTF/Godot ใช้ +Y ขึ้น และด้านหน้าเครื่องเป็น +Z
จุด Socket ใช้แกน local +Z ของ glTF หันออกจากช่องเสียบ เช่นเดียวกับโมเดลอุปกรณ์ก่อนหน้า

- RAM และ NIC: ยกขึ้นตาม +Y ใน Godot หลังปลดตัวยึดในลำดับเกมเพลย์ที่พัฒนาภายหลัง
- ถาด SSD: เลื่อนออกด้านหน้าตาม +Z ใน Godot
- PSU: เลื่อนออกด้านหลังตาม -Z ใน Godot
- ฝาเครื่อง: เลื่อนถอยหลังเล็กน้อยแล้วจึงยกขึ้น

จุดเหล่านี้เป็นจุดอ้างอิงงานเกม ไม่ใช่ขนาดเผื่อการประกบของอุปกรณ์จริง
ยังไม่ได้ทดสอบประกบหัวสาย Cat6 กับพอร์ตในฉาก Godot และยังไม่มีรางแร็กภายนอกหรือสายไฟ AC แยกชิ้น

## ขอบเขตความสมจริงและสิ่งที่ยังไม่ได้ทำ

โมเดลเน้นรูปร่างอุปกรณ์ บทบาทของพอร์ต และตำแหน่งชิ้นส่วนที่ต้องเรียนรู้
รายละเอียด PCB, ลายวงจร, จำนวน pad บน DIMM/PCIe, สายภายในและวงจรจ่ายไฟถูกย่อเพื่อให้มองเห็นง่าย
**ไม่ควรใช้ภาพนี้เป็นคู่มือเข้าขั้วไฟ คู่มือซ่อม หรือแผนผังวงจรของเซิร์ฟเวอร์จริง**
ไม่มีชิ้นส่วนไฟแรงสูงภายใน PSU ให้เปิดดู

ยังไม่มีระบบคลิก/ลากวาง, ลำดับประกอบ, collision, แอนิเมชันสำเร็จรูป, POST, ไฟสถานะอัตโนมัติ หรือบริการแชร์ไฟล์
คำว่า File Server เป็นบทบาทที่จะกำหนดด้วยซอฟต์แวร์และเควสภายหลัง ไม่ใช่สิ่งที่โมเดล 3D ทำงานได้เอง
การซ่อนฝาและเปิดดูภายในในภาพเป็นการจัดพรีวิว ไม่ใช่หลักฐานว่าเควสประกอบเครื่องเสร็จแล้ว

เมื่อทำระบบเควส ให้มีขั้นปิดเครื่องและตัดไฟก่อนถอดชิ้นส่วน จัดการ ESD และตรวจงานก่อนเปิดระบบ
การเปลี่ยนค่าที่ parent ในไฟล์นี้เป็นเพียงการเตรียม asset ไม่ได้จำลองกลไกล็อกหรือความปลอดภัยให้เอง

## สร้างใหม่และตรวจไฟล์

รันจากโฟลเดอร์ `assets/3Dmodel`:

```powershell
& '.\scripts\run_build_server.ps1'
& '.\scripts\run_build_server.ps1' -ValidateOnly
```

ตัวรันใช้ Blender ที่ติดตั้งอยู่บน C: แต่เปลี่ยน TEMP/cache/user config ของกระบวนการนี้ไปอยู่ใน `temp/server` บน D:
คำสั่งสร้างใหม่จะเขียนทับเฉพาะผลลัพธ์ชื่อ `rack_server_2u` ของงานนี้ หากแก้ Blender ด้วยมือให้เก็บชื่อเวอร์ชันใหม่ก่อนสร้างซ้ำ
ไม่แก้ Switch, Laptop, Printer, Cat6 หรือไฟล์ฉากเกมเดิม

การตรวจประกอบด้วย GLB reimport, จำนวนหน้าสัมผัส, ตำแหน่ง Socket, สถานะ LED เริ่มต้น, ยิง ray ผ่านช่อง LAN/AC/USB/VGA และลองเคลื่อนชิ้นส่วนจริงในหน่วยความจำ
เป็นการตรวจใน Blender **ไม่ใช่การทดสอบเกมเพลย์ Godot หรือการรับรองอุปกรณ์จริง**
