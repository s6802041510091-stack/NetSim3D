# Phase 5 — ฉากโรงเรียนและเมืองในเกมหลัก

สถานะ ณ 18 ตุลาคม 2026: ฉากใหม่เข้าเกม Godot หลักแล้ว และส่งออก Web release ได้
แต่ยังไม่ได้ยืนยันการโหลดและอัตราเฟรมในเบราว์เซอร์จริง

## สิ่งที่เข้าเกมแล้ว

- โรงเรียนที่เพิ่มหน้าต่างและกระจกจริงใน `assets/models/classroom_shell.glb`
  (บีบอัดจากไฟล์ Preview ด้วย gltfpack โดยใช้ `-kn -km -noq` เพื่อคงชื่อชิ้นส่วน
  สำหรับประตูและคอมพิวเตอร์ และเลี่ยงส่วนขยาย glTF ที่ Godot รุ่นนี้ไม่รองรับ)
- การชนของฉากปัจจุบันครบชุด รวมผนังที่เจาะช่องหน้าต่างและกระจก 62 แผ่นใน
  `data/map_collisions_phase5.json`; สร้างซ้ำจากต้นฉบับ Blender ได้ด้วย
  `tools/phase5_collision_manifest.py` โดยยังเก็บ `data/map_collisions.json` เดิมไว้
- เมืองประกอบรอบโรงเรียนใน `assets/exterior/` พร้อมอาคาร 72 หลัง,
  คนเดิน 14 คน, คนปั่นจักรยาน 6 คน, ท้องฟ้าและภูเขาภาพสองมิติ
  คนและอาคารรอบนอกเป็นฉากประกอบ ไม่มีการชนหรือภารกิจในพื้นที่เมือง
- ปรับจุดหมุนประตูห้องเรียน ห้องพักครู และห้อง Server ให้ตรงกับโมเดลโรงเรียนใหม่
- เครดิตโมเดลเมืองภายนอกอยู่ที่ `assets/exterior/ATTRIBUTION.md` และรวมไปกับ Web export

## การตรวจที่ผ่าน

- `tools/validate_phase5.gd`: ฉากหลัก หน้าต่าง กระจก การชน ประตู คอมพิวเตอร์ และอาคาร
- `tools/validate_doors.gd`: ประตู 8 บาน เดินเข้า–ออกด้วยตัวละครจริงครบ 16 ทิศทาง,
  ระดับบานประตู/จุดหมุน และป้องกันปิดทับตัวละคร
- `tools/validate_map_alignment.gd`: ตัวชนคงที่ 396 ชิ้นเทียบกับโมเดลที่ Godot โหลดจริง,
  ทดสอบพื้น/กระจก และเดินต่อเนื่องผ่านทางเดินที่ขยายแล้วเข้าห้องคอม
- `tools/validate_classroom_frame.gd`: ระยะขอบบานห้องคอมกับวงกบทุกด้าน, ระนาบบาน,
  จุดหมุน, ตัวชนบาน และตำแหน่งหลังเปิด–ปิดแบบมีแอนิเมชันซ้ำ 3 รอบ
- `tools/validate_import.gd`, `validate_computers.gd`, `validate_player_movement.gd`
- `tools/validate_mission_01.gd`, `validate_mission_05.gd`,
  `validate_mission_06.gd` (Network Designer รุ่นเก่าถูกถอดออกแล้ว ใช้ NetPlan EDU สำหรับด่าน 1)
- เปิดแพ็กเกจ `index.pck` ที่ส่งออกด้วย Godot แล้วรันตัวตรวจ Phase 5 ผ่าน
- ภาพทดสอบจากมุมหน้าต่างห้องเรียนและห้องวิทยาศาสตร์แสดงเมืองและภูเขาครบ

การทดสอบภารกิจที่บันทึกข้อมูลต้องให้ `user://` เขียนได้; ในสภาพแวดล้อมจำกัดสิทธิ์
ของการทดสอบครั้งนี้ใช้โฟลเดอร์ชั่วคราวภายใน workspace เท่านั้น ไม่เปลี่ยนการตั้งค่าเกม

## Web release

ส่งออกด้วย preset `Web` ใน `export_presets.cfg` โดยปิด thread support:
แพ็กเกจ `.pck` ประมาณ 159 MB, ไฟล์ `.wasm` ประมาณ 39.5 MB,
รวมไฟล์ส่งออกประมาณ 199 MB (ก่อนบีบอัดที่ระดับเว็บเซิร์ฟเวอร์)
ขนาดนี้ยังสูงสำหรับเกมเว็บ และยังต้องทดสอบเวลาโหลด/เฟรมเรตใน Chrome หรือ
เบราว์เซอร์ปลายทางจริงก่อนเผยแพร่ ผลตรวจแพ็กเกจด้วย Godot ไม่ถือเป็นผลทดสอบ
การเล่นในเบราว์เซอร์ ดูผลทดสอบเว็บเบื้องต้นด้านล่าง

### ทดสอบเว็บเบื้องต้น — 18 ตุลาคม 2026

เพิ่มเติม: ผู้ใช้ลองเล่นผ่าน Chrome ปกติและยืนยันว่าเล่นได้ พร้อมภาพห้องเรียน
และวิวเมืองจากหน้าต่าง แต่ยังรู้สึกหน่วง จึงผ่านเฉพาะ smoke test การเล่นบนเว็บ
งานวัด/ปรับประสิทธิภาพเลื่อนไว้ภายหลังตามที่ผู้ใช้ขอ

- เปิด Web export ผ่าน HTTP ที่ `http://127.0.0.1:8765/` ในเบราว์เซอร์ภายในแอป
  ได้จริง เห็นฉากเริ่มต้นห้อง IT Support พร้อมโมเดลและพื้นผิว
- พบ `WrongDocumentError: The root document of this element is not valid for pointer lock.`
  ตอนเริ่มและหลังคลิก canvas; ทดสอบ W และ D แล้วภาพไม่แสดงการเคลื่อนที่
- `player_controller.gd` จำกัดการเดินและการโต้ตอบไว้เมื่อจับเมาส์ได้ จึงยังยืนยัน
  การเดิน การเปิดประตู และการใช้คอมพิวเตอร์ในเว็บไม่ได้ ไม่ได้ปิดเงื่อนไขนี้เพื่อให้ทดสอบผ่าน
- ยังแยกไม่ได้ว่าปัญหา pointer lock เกิดเฉพาะเบราว์เซอร์ฝังตัวหรือเกิดใน Chrome ปกติด้วย
  ต้องทดสอบ Chrome/Edge แบบแท็บปกติต่อ ก่อนสรุปว่าเป็นข้อบกพร่องของเกม
- ยังไม่ได้วัด FPS หน่วยความจำ และเวลาโหลดอย่างเป็นระบบ การโหลดผ่าน localhost
  ไม่ใช่ตัวแทนความเร็วดาวน์โหลดของผู้เล่นผ่านอินเทอร์เน็ต; Phase 5 ฝั่งเว็บยังไม่ปิดงาน
- หลักฐานภาพเฉพาะเครื่อง: `tmp/godot-4.7.1/phase5-browser-smoke.jpg`
  ไม่มีการเผยแพร่เว็บหรือแก้พฤติกรรมเกมในการทดสอบครั้งนี้

## แก้ตัวชนค้างจากแมพเดิม — 18 ตุลาคม 2026

- สาเหตุ: ตัวสร้างข้อมูลชนรอบแรกอัปเดตเฉพาะผนังหน้าต่าง 9 ชิ้น แต่ยังใช้พิกัดเก่า
  ของส่วนอื่น ทั้งที่ปีกขวาเลื่อน +2.9645 เมตรและทางเดินกว้างขึ้นแล้ว
  จึงมี `Right_Corridor_Extension_Segment_0` ที่มองไม่เห็นขวางผู้เล่นบริเวณ x=-6.44
- แก้ตัวสร้างให้ใช้รายการชื่อ/ประเภทจาก manifest เดิมเท่านั้น ส่วนพิกัด ขนาด และ
  ผิวสามเหลี่ยมทั้งหมดคำนวณใหม่จาก evaluated geometry ของไฟล์ lookdev ปัจจุบัน
  ไม่บันทึกทับ Blender และไม่ย้ายโมเดลเพื่อหลบตัวชนเก่า
- ประตูที่ต้นฉบับกางไว้ประมาณ 65° ปรับการเปิดในเกมเป็นอย่างน้อย 90° โดยคงจุดหมุน
  และตำแหน่งตอนปิดเดิม เพื่อไม่ให้ตัวละครติดปลายบานเวลาเดินย้อนออกจากห้อง
- การตรวจรอบนี้ยืนยันเพียงว่าบานไม่ลอยสูง แต่ยังไม่ได้ตรวจระยะขอบบานกับวงกบ
  ครบทุกด้าน จึงต้องแก้บานห้องคอมต่อในหัวข้อถัดไป
- การทดสอบเดิมยิง ray สั้นรอบช่องประตูและเดินเฉพาะห้อง IT Support จึงไม่พบตัวชน
  ค้างกลางทางเดิน เพิ่มการเทียบตัวชนกับภาพและเดินหลายห้องเพื่อป้องกันเกิดซ้ำ

## แก้บานห้องคอมไม่พอดีวงกบ — 18 ตุลาคม 2026

- ตรวจใกล้แล้วพบว่าต้นฉบับ `Door_Leaf_Open_63deg` กว้าง 96 ซม. ในช่อง 100 ซม.,
  เว้นด้านบานพับถึง 4 ซม. แต่ด้านกลอนชิดวงกบ และระนาบบานเยื้อง 2.86 ซม.
  การทดสอบกึ่งกลาง/ระดับพื้นเดิมจึงยังไม่ครอบคลุมความพอดีกับวงกบ
- `3Dmodel/scripts/fit_classroom_door.py` แก้เฉพาะบานนี้ในไฟล์ lookdev เป็นกว้าง
  99.2 ซม., ช่องด้านข้างและด้านบน 4 มม., ใต้บาน 8 มม.; จัดบานเข้าระนาบวงกบ
  และย้ายจุดหมุน `ClassroomDoor` ใน Godot ไปที่ขอบในของวงกบเดียวกัน
- เก็บต้นฉบับก่อนแก้ใน `working/classroom_shell_lookdev_before_door_frame_fix.blend`
  และตรวจว่าอีก 10,770 วัตถุไม่เปลี่ยนตำแหน่งหรือรูปทรง ไม่แตะประตูอีก 7 ห้อง
- ส่งออกโรงเรียนและข้อมูลชนจากต้นฉบับใหม่ โดยใช้ gltfpack `-kn -km -noq` เช่นเดิม

ไฟล์ Web export ระหว่างพัฒนาเก็บใน `tmp/phase5_web_export/` ซึ่งไม่อยู่ใน Git
เมื่อจะเผยแพร่ ให้ส่งออกใหม่จากโปรเจกต์ Godot แล้วทดสอบผ่าน HTTP(S)
ในเบราว์เซอร์เป้าหมาย ไม่เปิด `index.html` ผ่าน `file://`

## เปิดช่องบันไดลงที่ถูกฉากเมืองปิด — 19 ตุลาคม 2026

  ยื่นปิดช่องบันไดลงใกล้ระดับพื้น 0 เมตร ตัวชนบันไดเดิมไม่ได้ขวาง
- เปิดช่องเฉพาะด้านในผนังช่องบันได ลงถึง -3.60 เมตรในต้นฉบับ `town.blend`
  แล้วส่งออก `town.glb` ทั้ง Preview และเกม ไม่เปลี่ยนขั้นบันไดหรือ collider โรงเรียน

  และเก็บต้นฉบับก่อนแก้ใน `tmp/town_before_stairwell_fix.blend`
- `tools/inspect_stair_obstruction.gd` ตรวจผิวโมเดลเมืองเหนือบันได 3 ตำแหน่ง
  พร้อมจำลองเดินจริงลงถึง y=-3.349 และกลับขึ้นถึง y=0.000 ผ่าน failures=0

  ฉากรวมล่าสุดให้สร้างใหม่ด้วย `school_town.py --combine`; เกมอ่าน town.glb ที่แก้แล้ว
