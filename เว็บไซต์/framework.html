02ผู้ใช้แต่ละบทบาททำอะไรบ้าง

นักเรียน

  1. กด “เข้าสู่ระบบด้วย Google”
  2. ครั้งแรก: เลือกบทบาท “นักเรียน”
  3. กรอก Class ID และ รหัสผ่านคลาส ที่ครูให้ เพื่อเข้าคลาส (เข้าได้หลายคลาส)
  4. เลือก Simulation เข้าหน้า workspace หรือ Game เข้าเมนูเกม
  5. เล่นเกมเรียงด่าน 1 ถึง 6 (ด่านถัดไปเปิดเมื่อผ่านด่านก่อน) และกลับไปเล่นด่านที่ผ่านแล้วซ้ำได้ ทั้งสองอย่างเกมทำได้อยู่แล้ว
  6. เล่นจบด่าน เกมส่งคะแนนขึ้นระบบให้เอง หน้า “ความคืบหน้า” ในเกมเห็นผลของตัวเองทุกครั้ง ไม่ว่าเล่นจากเครื่องไหน

ครู

  1. กด “เข้าสู่ระบบด้วย Google”
  2. ครั้งแรก: เลือกบทบาท “ครู” (ใช้ได้เฉพาะอีเมลที่ภาคอนุญาต ดูหัวข้อ 09)
  3. สร้างคลาส ระบบสร้าง Class ID ให้ ครูตั้ง รหัสผ่านคลาส แล้วแจ้งนักเรียน
  4. กด Simulation หรือ Game เข้าหลังบ้านของส่วนนั้น
  5. Dashboard: คะแนนทุกคนในคลาส ราย ด่าน/แล็บ ราย ครั้ง จุดที่ผิดพลาด แล้วกด Export CSV
  6. จัดการคลาส: แก้ชื่อ เปลี่ยนรหัสผ่าน หรือลบคลาส

Dashboard แสดงคะแนนอย่างไร

  • บันทึกทุกครั้งที่เล่น พร้อมวันเวลา จึงรู้ว่าครั้งไหนเป็น ครั้งแรก
  • ตารางสรุปแต่ละคน แสดง 3 ค่า: ครั้งแรก (วัดความเข้าใจตอนเริ่ม), ดีที่สุด, ล่าสุด และจำนวนครั้งที่เล่น
  • เลือกด่าน 1 ถึง 6 เพื่อดูว่าใครเล่นแล้ว ใครยังไม่เล่น
  • กดชื่อนักเรียนเพื่อดูประวัติทุกครั้ง และจุดที่ผิดพลาดแต่ละครั้ง

เรื่องที่ควรตกลงเพิ่ม

  • ลบคลาส: ให้ยืนยันก่อน และเก็บคะแนนไว้ในระบบแบบซ่อน (กู้คืนได้) ดีกว่าลบทิ้งทันที
  • เปลี่ยนรหัสผ่านคลาส: มีผลกับคนที่จะเข้าใหม่เท่านั้น นักเรียนที่อยู่ในคลาสแล้วไม่ถูกถอดออก
  • “สร้างบัญชี”: ล็อกอิน Google ครั้งแรกถือเป็นการสร้างบัญชี ไม่ต้องตั้งรหัสผ่านเอง
  • ฝั่งนักเรียน: Lobby มี Join Class, เลือกคลาส, เข้าเกม และดูคะแนนตัวเอง

07API ที่ต้องมี

คำขอเส้นทางใครเรียกทำอะไร
POST/api/auth/googleทุกคนรับ ID token จาก Google ตรวจแล้วออก session
POST/api/auth/logoutทุกคนออกจากระบบ
GET/api/meทุกคน, เกมชื่อ บทบาท คลาสที่อยู่
POST/api/me/roleผู้ใช้ใหม่เลือกบทบาทครั้งแรก (ครูต้องอยู่ใน allowlist)
POST/api/classesครูสร้างคลาส ได้ Class ID ตั้งรหัสผ่าน
GET/api/classesครู, นักเรียนคลาสของฉัน
PATCH/api/classes/:idครูเจ้าของคลาสแก้ชื่อคลาส, เปลี่ยนรหัสผ่าน, เปิด/ปิดรับสมาชิก
DELETE/api/classes/:idครูเจ้าของคลาสลบคลาส (ซ่อนไว้ กู้คืนได้)
POST/api/classes/joinนักเรียนเข้าคลาสด้วย Class ID + รหัสผ่าน
POST/api/game/attemptsเกมส่งผลการเล่นหนึ่งครั้ง
GET/api/game/attempts/meเกมประวัติของฉัน (หน้า “ความคืบหน้า” ในเกม)
POST/api/sim/submissionsSimulationส่งผลแล็บ
GET/api/classes/:id/game-resultsครูเจ้าของคลาสDashboard เกม
GET/api/classes/:id/sim-resultsครูเจ้าของคลาสDashboard Simulation
GET/api/classes/:id/export.csvครูเจ้าของคลาสดาวน์โหลด CSV (เลือกได้: เกม, Simulation, ทั้งหมด)

CSV หนึ่งแถวต่อการเล่นหนึ่งครั้ง: รหัสนักศึกษา/อีเมล, ชื่อ, ด่าน, ครั้งที่, คะแนนรวม, ความถูกต้อง, กระบวนการ, เวลา, ดาว, ผ่าน/ไม่ผ่าน, เวลาที่ใช้, จุดที่ผิดพลาด, วันเวลา บันทึกเป็น UTF-8 แบบมี BOM เพื่อให้ Excel เปิดภาษาไทยได้ถูก

08สิ่งที่ต้องเพิ่มในเกม NetSim3D

ด่าน ภารกิจ และวิธีคิดคะแนนไม่เปลี่ยน เพิ่มเฉพาะการเชื่อมกับระบบ

ตอนเปิดเกม

  • เรียก GET /api/me ถ้ามี session แสดงชื่อและคลาสที่มุมเมนู
  • ถ้าไม่มี session (เปิดเกมตรง ๆ) ขึ้นปุ่ม “เข้าสู่ระบบ” พากลับหน้าเว็บหลัก
  • ตั้งค่าเกม (ภาษา เสียง ภาพ) ยังเก็บในเครื่องเหมือนเดิม

ตอนเล่นจบด่าน

  • GameProgress.record_attempt เก็บในเครื่องเหมือนเดิม แล้วส่ง POST /api/game/attempts
  • ส่งไม่สำเร็จ: เข้าคิวในเครื่อง แล้วลองส่งใหม่ตอนเปิดเกมหรือจบด่านถัดไป
  • ใช้ HTTPRequest ของ Godot เรียก API โดเมนเดียวกัน คุกกี้ไปเอง

หน้า “ความคืบหน้า”

  • อ่านประวัติจาก GET /api/game/attempts/me เห็นผลเดียวกันทุกเครื่อง
  • หน้าตาเดิมทั้งหมด (กราฟ ตาราง จุดที่ผิดพลาด)
  • ถ้าออฟไลน์ แสดงจากข้อมูลในเครื่อง

09ความปลอดภัยและข้อมูลส่วนบุคคล

เรื่องที่ต้องตัดสินใจ: ถ้าใครก็กดเลือกบทบาทครูได้ นักเรียนจะสร้างคลาสหรือเข้าไปดูคะแนนคนอื่นได้ แนะนำให้บทบาทครูใช้ได้เฉพาะอีเมลในรายชื่อที่ภาคกำหนด (ตาราง teacher_allowlist) หรือให้แอดมินอนุมัติ

  • รหัสผ่านคลาสเก็บแบบ hash (bcrypt) และจำกัดจำนวนครั้งที่ลองผิด เช่น 5 ครั้งต่อ 10 นาที
  • ครูเห็นเฉพาะคลาสของตัวเอง นักเรียนเห็นเฉพาะผลของตัวเอง ตรวจสิทธิ์ที่ API ทุกคำขอ ไม่พึ่งการซ่อนปุ่มในหน้าเว็บ
  • Session cookie แบบ HttpOnly, Secure, SameSite=Lax ทุกอย่างผ่าน HTTPS
  • เก็บข้อมูลส่วนตัวเท่าที่ต้องใช้ (ชื่อ อีเมล) อยู่บนเซิร์ฟเวอร์ภาค สอดคล้อง PDPA และแจ้งนักเรียนในหน้าแรกว่าเก็บอะไรบ้าง
  • สำรองฐานข้อมูลอัตโนมัติทุกวัน

ถ้าเซิร์ฟเวอร์รัน Docker ได้ (แผน A)

ยกทั้งระบบด้วย docker compose up -d ข้อมูลทั้งหมดอยู่ในภาค ดูแลและย้ายเครื่องง่าย

ถ้าวางได้แค่ไฟล์เว็บ (แผน B)

หน้าเว็บ เกม และ Simulation วางบนเซิร์ฟเวอร์ภาค ส่วนล็อกอินและฐานข้อมูลใช้ Supabase (มี Google login ในตัว) แต่ข้อมูลนักเรียนจะอยู่บนคลาวด์นอกมหาวิทยาลัย ต้องถามอาจารย์ก่อน

ไฟล์เกมรวมราว 180 MB (index.pck 141 MB + wasm 40 MB) ตั้ง Nginx ให้บีบอัดและแคชไว้ในเบราว์เซอร์ นักเรียนโหลดเต็มแค่ครั้งแรก

12คำถามที่ต้องได้คำตอบก่อนเริ่ม

เซิร์ฟเวอร์ภาค

รัน Docker หรือโปรแกรมฝั่งเซิร์ฟเวอร์ได้ไหม มีฐานข้อมูลแบบไหน มี HTTPS และโดเมนหรือยัง เข้าจัดการทาง SSH ได้ไหม

บัญชี Google

บังคับให้ใช้เฉพาะอีเมลมหาวิทยาลัยไหม ใครเป็นคนสร้าง OAuth Client ใน Google Cloud (ภาค หรือนักศึกษา)

บทบาทครู

ใช้ allowlist อีเมล หรือให้แอดมินอนุมัติ ใครเป็นแอดมิน

คะแนน Simulation

แต่ละแล็บตรวจอะไร ให้คะแนนแบบไหน ต้องมีประวัติรายครั้งเหมือนเกมไหม

ใครทำส่วนไหน

หน้าเว็บหลัก Simulation API และเกม แบ่งงานกันอย่างไร

ข้อมูลใน CSV

ต้องมีรหัสนักศึกษาไหม (บัญชี Google อาจไม่มี) ถ้าต้องมี ให้นักเรียนกรอกครั้งแรกตอนเข้าคลาส
