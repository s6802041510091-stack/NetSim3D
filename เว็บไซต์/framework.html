สถาปัตยกรรมระบบ NetSim

กรอบการทำงานของทั้งระบบ ตั้งแต่เข้าสู่ระบบจนครูเปิดดูคะแนนและดาวน์โหลด CSV ใช้คุยกับอาจารย์ที่ปรึกษาและเพื่อนร่วมโปรเจกต์ ทุกส่วนวางบนเซิร์ฟเวอร์ของภาควิชา ใช้กับนักเรียนชั้น ปวช.3 ส่วน Simulation (Net-Desktop) ใช้ประกอบการสอนและวัดผลการเรียน ส่วนเกม NetSim3D ใช้วัดผลอย่างเดียว

ร่าง 20 พ.ย. 2569 · ปรับตามของจริง 25 พ.ย. 2569 สร้างแล้ว: ระยะ 1–5 ในโฟลเดอร์ web-portal (branch claude/web-portal) ยังต้องทำ: Google Login, ขึ้นเซิร์ฟเวอร์ภาค, เชื่อม Net-Desktop (ระยะ 6)

02แผนผังหน้าเว็บ

เส้นทางหน้าใครเห็นสถานะ
/หน้าแรก: แนะนำระบบ ปุ่มเข้าสู่ระบบ ประกาศว่าเก็บข้อมูลอะไรทุกคนทำแล้ว
/loginเข้าสู่ระบบ: ปุ่ม Google และล็อกอินทดสอบ (ใช้ตอนพัฒนาเท่านั้น)ทุกคนทำแล้ว Google ยังไม่เปิด
/welcome/roleเลือกบทบาทครั้งเดียว ครูเลือกได้เฉพาะอีเมลในรายชื่อที่อนุญาตผู้ใช้ใหม่ทำแล้ว
/welcome/profileข้อมูลนักเรียน: ชื่อ, นามสกุล, รหัสนักศึกษา 13 หลัก (แก้ภายหลังได้จากปุ่ม "ข้อมูลของฉัน")นักเรียนทำแล้ว
/lobbyห้องเรียนนักเรียน: คลาสที่กำลังเรียน, เข้าคลาส, คลาสของฉัน, ปุ่มเข้า Simulation และเกมนักเรียนทำแล้ว
/lobbyห้องเรียนครู: สร้างคลาส, คลาสของฉัน, คลาสที่ลบแล้ว (กู้คืน), เครื่องมือครูครูทำแล้ว
/classes/:idหน้าคลาส แท็บ "นักเรียนและตั้งค่า": Class ID พร้อมปุ่มคัดลอก, รายชื่อ, นำออก, แก้ชื่อ, เปลี่ยนรหัสผ่าน, เปิด/ปิดรับสมาชิก, ลบคลาสครูเจ้าของคลาสทำแล้ว
/classes/:id?tab=gameหน้าคลาส แท็บ "คะแนนเกม": ภาพรวม 6 ด่าน, รายด่าน, ประวัติรายคน, ดาวน์โหลด CSVครูเจ้าของคลาสทำแล้ว
/game/เกม NetSim3Dนักเรียน (ครูทดลองเล่นได้)ทำแล้ว
/sim/Simulation (Net-Desktop)นักเรียนทำแล้ว ยังใช้ล็อกอินของตัวเอง
/sim/teacher.htmlหน้าครูของ Net-Desktop: ผลก่อน–หลังเรียน ภารกิจ CSVครูทำแล้ว ยังใช้รหัสผ่านครูของตัวเอง
ไม่มีหน้าแอดมินรายชื่ออีเมลครูตั้งไว้ในค่า TEACHER_EMAILS ของเซิร์ฟเวอร์ผู้ดูแลระบบทำแล้ว

การไปมาระหว่างหน้า

  • หน้าที่ต้องล็อกอินจะพาไป /login ก่อน ถ้ายังไม่เลือกบทบาทหรือยังไม่กรอกข้อมูลนักเรียน จะพาไปหน้านั้นก่อนเสมอ
  • คลาสแรกที่นักเรียนเข้าจะเป็น "คลาสที่กำลังเรียน" ให้อัตโนมัติ เปลี่ยนได้ที่ห้องเรียน คะแนนเกมเข้าคลาสนี้
  • ปุ่ม Simulation และเกมในห้องเรียนกดได้เมื่อเข้าคลาสแล้ว
  • ปุ่ม "กลับล็อบบี้" ในเกมพากลับหน้าแรก ซึ่งจะมีปุ่ม "ไปที่ห้องเรียนของฉัน"
  • Net-Desktop ยังไม่มีลิงก์กลับเว็บหลัก (ทำในระยะ 6)
  • ทุกหน้าสลับไทย/English ได้ หน้าตาเข้าชุดกับเกม (ฟอนต์ Mitr ภาพโรงเรียนซากุระ แผงกระจก) และใช้บนมือถือได้

03ผู้ใช้แต่ละบทบาททำอะไรบ้าง

นักเรียน

  1. กด "เข้าสู่ระบบ" (ตอนนี้ใช้ล็อกอินทดสอบ ภายหลังเป็น Google)
  2. ครั้งแรก: เลือกบทบาท "นักเรียน" แล้วกรอกชื่อ นามสกุล และรหัสนักศึกษา 13 หลัก (อีเมลได้จากบัญชีที่ล็อกอิน)
  3. เข้าคลาสด้วย Class ID และรหัสผ่านคลาสที่ครูให้ (เข้าได้หลายคลาส เลือกคลาสที่กำลังเรียนได้)
  4. กด Simulation เพื่อเรียนและฝึก หรือกด Game เพื่อทำภารกิจวัดผล
  5. เล่นเกมเรียงด่าน 1 ถึง 6 และกลับไปเล่นด่านที่ผ่านแล้วซ้ำได้
  6. จบด่านแล้วเกมส่งคะแนนให้ครูเอง หน้า "ความคืบหน้า" ในเกมเห็นผลของตัวเองเหมือนกันทุกเครื่อง

ครู

  1. กด "เข้าสู่ระบบ" แล้วเลือกบทบาท "ครู" (เฉพาะอีเมลในรายชื่อที่อนุญาต)
  2. สร้างคลาส: ระบบสร้าง Class ID 6 ตัวอักษรให้ (ไม่มีตัวที่สับสนง่ายอย่าง 0/O, 1/I) ครูตั้งรหัสผ่านคลาส แล้วแจ้งนักเรียน
  3. หน้าคลาส: ดูรายชื่อ นำนักเรียนออก แก้ชื่อคลาส เปลี่ยนรหัสผ่าน เปิด/ปิดรับสมาชิก ลบหรือกู้คืนคลาส
  4. แท็บ "คะแนนเกม": ดูคะแนนทุกคน รายด่าน รายครั้ง จุดที่ผิดพลาด แล้วดาวน์โหลด CSV
  5. ผลของ Simulation ดูที่หน้าครูของ Net-Desktop ไปก่อน (รวมเข้าหน้าคลาสในระยะ 6)

แท็บคะแนนเกมแสดงอะไร

  • ภาพรวม: นักเรียน × 6 ด่าน แต่ละช่องเป็นคะแนนดีที่สุดพร้อมดาวและจำนวนครั้ง (ผ่านสีเขียว ไม่ผ่านสีแดง)
  • รายด่าน: เล่นแล้วกี่คน ผ่านกี่คน คะแนนดีที่สุดเฉลี่ย และของแต่ละคน: ครั้งแรก (วัดความเข้าใจตอนเริ่ม), ดีที่สุด, ล่าสุด, จำนวนครั้ง คนที่ยังไม่เล่นขึ้นก่อน
  • กดชื่อนักเรียน: ทุกครั้งที่เล่น คะแนนแต่ละส่วน เวลาแต่ละขั้น และจุดที่ผิดพร้อมเหตุผลและวินาทีที่ผิด
  • นักเรียนที่ถูกนำออกจากคลาสยังเห็นผลเดิม มีป้าย "ออกจากคลาสแล้ว"

ที่ตกลงและทำแล้ว

  • ลบคลาส: ต้องกดยืนยัน ซ่อนไว้ ข้อมูลและคะแนนยังอยู่ กู้คืนได้
  • เปลี่ยนรหัสผ่านคลาส หรือปิดรับสมาชิก: นักเรียนที่อยู่ในคลาสแล้วยังอยู่เหมือนเดิม
  • ล็อกอินครั้งแรกถือเป็นการสร้างบัญชี ไม่ต้องตั้งรหัสผ่านเอง
  • เลือกบทบาทได้ครั้งเดียว

04เทคโนโลยีที่ใช้จริง

ส่วนใช้หมายเหตุ
หน้าเว็บหลักReact 19 + Vite + TypeScript + React Routerไทย/อังกฤษ, ฟอนต์และภาพจากเกม
API กลางNode.js 24 + Express 5 + TypeScript, pg, zod, bcryptjsแบบเดียวกับ Net-Desktop เพื่อนอ่านต่อได้ Node 24 รันไฟล์ .ts ได้เลยไม่ต้อง build
ฐานข้อมูลPostgreSQL 16 ในคอนเทนเนอร์ Dockerตารางสร้างอัตโนมัติจากไฟล์ migrations/ ตอนเปิด API
Simulation Net-DesktopHTML/JS + Express + SQLite จากรีโป Mxles-Arm/Net-Desktopไม่แก้โค้ดเพื่อน ยกเว้นเปลี่ยน /api/ เป็น api/ อัตโนมัติตอนสร้างคอนเทนเนอร์
เกม NetSim3DGodot 4.7 ส่งออกเป็น Web + autoload ServerSyncด่านและวิธีคิดคะแนนเหมือนเดิม
เข้าสู่ระบบตอนนี้: ล็อกอินทดสอบ (DEV_LOGIN) · จริง: Google Identity ServicesGoogle รอ OAuth Client
เว็บเซิร์ฟเวอร์Nginxบีบอัดไฟล์เกมไว้ก่อน (.wasm 37.7 MB เหลือ 9.7 MB)
ติดตั้งDocker Compose: nginx, api, db, simคำสั่งเดียว docker compose up -d --build
ทดสอบAPI 48 ข้อ (node:test + supertest), เกมกับเว็บ 15 ข้อ (tools/check_server_sync.gd)

ทุกส่วนอยู่โดเมนเดียวกัน คุกกี้ล็อกอินจึงใช้ร่วมกันได้ เกมไม่ต้องล็อกอินซ้ำ

เปลี่ยนจากร่างแรก: ใช้ Express แทน Fastify + Prisma (ให้เหมือน Net-Desktop) และใช้ Net-Desktop เป็น Simulation แทนการสร้างใหม่ด้วย React

06นักเรียนเล่นเกม แล้วคะแนนไปถึงครูอย่างไร

เกมคำนวณคะแนนเหมือนเดิมทุกอย่าง (ความถูกต้อง 30 · กระบวนการ 50 · เวลา 20 ดาว และจุดที่ผิดพลาด) ที่เพิ่มคือ scripts/core/server_sync.gd (autoload ServerSync) ทำงานเฉพาะตอนเกมเปิดอยู่บนเว็บ NetSim

เน็ตหลุด

ผลรอในเครื่อง (pending_attempts.json) แล้วลองส่งใหม่ทุก 60 วินาทีและตอนเปิดเกม ส่งซ้ำก็บันทึกครั้งเดียว เพราะแต่ละครั้งมีรหัสของตัวเอง

เครื่องในห้องแล็บที่ใช้ร่วมกัน

ผลที่รอส่งติดชื่อคนเล่นไว้ และส่งเฉพาะตอนคนนั้นล็อกอินอยู่ ถ้าเปลี่ยนคนเล่นบนเครื่องเดิม ความคืบหน้าและเกมที่บันทึกค้างของคนก่อนจะถูกล้างจากเครื่อง

ป้ายบนเมนูเกม

มุมซ้ายบนบอกชื่อและคลาสของคนที่ล็อกอิน ถ้ายังไม่ล็อกอินจะเตือนว่า "คะแนนจะไม่ถูกส่งให้ครู" พร้อมปุ่มเข้าสู่ระบบ ครูทดลองเล่นได้แต่คะแนนไม่ถูกส่ง เปิดเกมนอกเว็บ (Godot editor หรือ web/serve.ps1) เกมทำงานแบบเดิม

Log คะแนนและไฟล์ CSV สำหรับครู

เว็บกลางเก็บข้อมูลผู้ใช้ 3 อย่าง: ชื่อ-นามสกุล, รหัสนักศึกษา และอีเมล ส่วนเกมและ Simulation เก็บ Log ตามที่ฟังก์ชันของแต่ละส่วนบันทึกอยู่แล้ว ไม่เพิ่มข้อมูลใหม่

เกม

บันทึกที่ GameProgress.record_attempt ทุกครั้งที่จบด่าน: คะแนนรวม, ความถูกต้อง 30, กระบวนการ 50, เวลา 20, ดาว, ผ่าน/ไม่ผ่าน, เวลาที่ใช้ทั้งด่าน, การตัดสินใจถูก/ทั้งหมด, จำนวนครั้งที่กดตรวจ, เวลาแต่ละขั้น (step_times) และจุดที่ผิดพลาด (mistake_log: ผิดอะไร เพราะอะไร ขั้นไหน วินาทีที่เท่าไร)

ในเครื่องนักเรียนเก็บย้อนหลังแค่ 30 ครั้งต่อด่าน บนเซิร์ฟเวอร์เก็บทุกครั้ง

Simulation

ใช้ข้อมูลที่ Net-Desktop เก็บอยู่แล้วไปก่อน: ภารกิจแต่ละครั้ง (เวลาเริ่ม/จบ, จำนวนครั้งที่ตรวจ, คำใบ้, ผ่าน, คะแนน, จุดที่ผิด), แบบทดสอบก่อน–หลังเรียน และแบบประเมิน ดาวน์โหลดจากหน้าครูของ Net-Desktop

ปรับรูปแบบ Log หลังแก้ Simulation ตามคอมเม้นอาจารย์ (ระยะ 6)

ไฟล์ CSV ของเกม (แท็บคะแนนเกม เฉพาะคลาสของตัวเอง เลือกด่าน ช่วงวันที่ และภาษาของหัวตารางได้)

ไฟล์หนึ่งแถวคือคอลัมน์
สรุปรายคนนักเรียน 1 คนรหัสนักศึกษา, ชื่อ, นามสกุล, อีเมล, แต่ละด่าน: ครั้งแรก/ดีที่สุด/ล่าสุด/จำนวนครั้ง
Log รายครั้งการเล่น 1 ครั้งรหัสนักศึกษา, ชื่อ, นามสกุล, อีเมล, ด่าน, ครั้งที่, วันเวลาจบ, เวลาที่ใช้, คะแนนรวม, ความถูกต้อง, กระบวนการ, เวลา, ดาว, ผ่าน, ตัดสินใจถูก, ตัดสินใจทั้งหมด, จำนวนครั้งที่ตรวจ, จุดที่ผิดพลาด
Log รายขั้นขั้น 1 ขั้นของการเล่น 1 ครั้งรหัสนักศึกษา, ชื่อ, นามสกุล, อีเมล, ด่าน, ครั้งที่, วันเวลาจบ, ขั้นที่, ชื่อขั้น, วินาทีที่ใช้, จำนวนจุดที่ผิด, จุดที่ผิด (ผิดอะไร เพราะอะไร วินาทีที่เท่าไร)
  • บันทึกเป็น UTF-8 แบบมี BOM ภาษาไทยใน Excel จึงไม่เพี้ยน และเวลาในไฟล์เป็นเวลาประเทศไทย
  • รหัสนักศึกษาเขียนเป็นข้อความ Excel จึงไม่แสดงเป็น 6.8E+12
  • ข้อความที่ขึ้นต้นด้วย = + - @ (เช่นชื่อที่นักเรียนพิมพ์เอง) ถูกกันไม่ให้ Excel รันเป็นสูตร

09ความปลอดภัยและข้อมูลส่วนบุคคล

  • บทบาทครูใช้ได้เฉพาะอีเมลในรายชื่อ (TEACHER_EMAILS) เอาอีเมลออกแล้วคนนั้นหมดสิทธิ์ครูทันที
  • รหัสผ่านคลาสเก็บแบบ bcrypt ใส่ผิด 5 ครั้งใน 10 นาทีจะถูกพักการเข้าคลาส
  • ครูเห็นเฉพาะคลาสของตัวเอง นักเรียนเห็นเฉพาะผลของตัวเอง ตรวจสิทธิ์ที่ API ทุกคำขอ
  • Session cookie แบบ HttpOnly และ SameSite=Lax ในฐานข้อมูลเก็บแค่ hash บนเซิร์ฟเวอร์จริงเปิด Secure ด้วย (COOKIE_SECURE=true)
  • คำขอที่เปลี่ยนข้อมูลต้องมาจากหน้าเว็บของเราเอง (ตรวจ Origin) และฐานข้อมูลไม่เปิดพอร์ตออกนอกเครื่อง
  • เก็บข้อมูลส่วนตัวเท่าที่ต้องใช้ (ชื่อ นามสกุล รหัสนักศึกษา อีเมล) หน้าแรกแจ้งนักเรียนว่าเก็บอะไรและเพื่ออะไร

ล็อกอินทดสอบ (DEV_LOGIN) ต้องปิดบนเซิร์ฟเวอร์จริง เพราะพิมพ์อีเมลใดก็เข้าได้

ข้อจำกัด: คะแนนเกมคำนวณในเบราว์เซอร์ เซิร์ฟเวอร์ตรวจได้แค่ว่าตัวเลขรวมกันถูกและอยู่ในช่วงที่เป็นไปได้ คนที่เชี่ยวชาญคอมพิวเตอร์มากปลอมคะแนนได้ในทางทฤษฎี

ใช้ Docker ทั้งระบบ รวมถึงฐานข้อมูล

ยกขึ้นด้วย docker compose up -d --build ข้อมูลทั้งหมดอยู่บนเซิร์ฟเวอร์ภาค ดูแลและย้ายเครื่องง่าย ฐานข้อมูลเก็บใน volume pgdata อัปเดตหรือสร้างคอนเทนเนอร์ใหม่ได้โดยข้อมูลไม่หาย Net-Desktop สร้างจากรีโปของเพื่อน ข้อมูลอยู่ใน volume simdata ไฟล์เกมไม่อยู่ใน Git ต้อง export จาก Godot ก่อน (node scripts/export-game.mjs)

ยังต้องทำก่อนใช้จริง

  • HTTPS (Let's Encrypt หรือใบรับรองของมหาวิทยาลัย) จำเป็นสำหรับ Google Login
  • สำรองข้อมูลด้วย pg_dump ทุกวัน เก็บไฟล์ไว้นอกคอนเทนเนอร์
  • ค่าตั้งของเซิร์ฟเวอร์จริง: DEV_LOGIN=false, COOKIE_SECURE=true, รายชื่ออีเมลครูจริง

ไฟล์เกมดาวน์โหลดราว 130 MB ต่อคนตอนเปิดครั้งแรก (index.pck 118 MB + wasm 9.7 MB หลังบีบอัด) เบราว์เซอร์เก็บไว้ใช้ครั้งต่อไป นักเรียนทั้งห้องเปิดพร้อมกันครั้งแรกใช้ bandwidth รวมหลาย GB ถ้าเครือข่ายภาครับไม่ไหวค่อยย้ายเฉพาะ .pck และ .wasm ไปฝาก CDN

12คำถามถึงอาจารย์

เซิร์ฟเวอร์ภาค

ระบบปฏิบัติการอะไร เข้าไปติดตั้งเองทาง SSH ได้ไหม ติดตั้งและรัน Docker (Engine + Compose) ได้ไหม รัน PostgreSQL ในคอนเทนเนอร์ของเราเองได้ไหม หรือต้องใช้ฐานข้อมูลกลางของภาค

โดเมนและเครือข่าย

เว็บจะได้โดเมนอะไร มี HTTPS ไหม (Google Login ต้องใช้) bandwidth พอไหม (เกมราว 130 MB ต่อคนตอนเปิดครั้งแรก) นักเรียนต้องเข้าจากนอกมหาวิทยาลัยได้ไหม

บทบาทครูและบัญชี Google

ใช้รายชื่ออีเมลครูที่ตั้งไว้ล่วงหน้าแบบตอนนี้พอไหม หรือต้องมีหน้าแอดมินอนุมัติ จำกัดเฉพาะอีเมลมหาวิทยาลัยไหม ใครสร้าง OAuth Client ใน Google Cloud

คะแนน Simulation

แต่ละภารกิจตรวจอะไร ให้คะแนนแบบไหน ต้องมีประวัติรายครั้งเหมือนเกมไหม (ใช้ตอนทำระยะ 6)

ความน่าเชื่อถือของคะแนนเกม

คะแนนคำนวณในเบราว์เซอร์ (หัวข้อ 09) ใช้วัดผลได้พอไหม หรือต้องให้เซิร์ฟเวอร์ตรวจซ้ำ

ระยะเวลาเก็บข้อมูล

ต้องเก็บข้อมูลนักเรียนและคะแนนไว้นานเท่าไร แล้วลบเมื่อไร (PDPA)

ได้คำตอบแล้ว

  • Simulation คือ Net-Desktop ของเพื่อนร่วมโปรเจกต์ นำมาวางในเว็บเดียวกัน
  • เก็บผลเกมทุกครั้ง ครูดูได้ทั้งครั้งแรก ดีที่สุด และล่าสุด
  • CSV มีรหัสนักศึกษา ชื่อ นามสกุล และอีเมล โดยให้นักเรียนกรอกครั้งแรกหลังเลือกบทบาท
  • ฐานข้อมูลใช้ PostgreSQL ใน Docker
  • Log ใช้ตามที่เกมและ Simulation บันทึกอยู่แล้ว
