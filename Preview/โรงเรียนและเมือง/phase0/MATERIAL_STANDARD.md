# มาตรฐานปรับภาพ — ฉบับเริ่มต้น

## แนวภาพ

ผู้ใช้อนุมัติภาพต้นแบบ Phase 1 และสั่งขยายสู่ Phase 2 เมื่อ 16 ตุลาคม 2026: ใช้โทนสว่างสะอาด ลายไม้โทนอุ่น กระเบื้องเทาอ่อน และรายละเอียดพื้นผิวระดับเดียวกับมุมโต๊ะ IT Support เป็นมาตรฐานต่อไป

โรงเรียนร่วมสมัย สมจริงแบบเกม ใช้งานจริงแต่สะอาด มีรอยใช้เล็กน้อย ไม่ทำฉากเก่าทรุดโทรมโดยไม่ได้รับอนุมัติ
ใช้ภาพอ้างอิงและขนาดจริงของอุปกรณ์ ไม่เพิ่ม polygon ทั่วฉากเพื่อให้ดูละเอียด

## รายการวัสดุต้นแบบ

| รหัสสำหรับวัสดุใหม่ | ผิว | รายละเอียดสำคัญ |
|---|---|---|
| MAT_ARCH_PaintedWall | สีผนัง | ผิวละเอียดอ่อนและความด้าน |
| MAT_ARCH_FloorTile | กระเบื้อง | รอยต่อ ขนาดแผ่นสม่ำเสมอ |
| MAT_ARCH_Ceiling | ฝ้า | ผิวและรอยต่อไม่เด่นเกินไป |
| MAT_WOOD_Laminate | ไม้โต๊ะ/ตู้ | ลายไม้มีทิศทางและขอบปิดผิว |
| MAT_METAL_PowderCoat | โลหะพ่นสี | สีเคลือบด้าน ไม่ตั้งโลหะทั้งผิวเหมือนเหล็กเปลือย |
| MAT_METAL_Aluminium | อะลูมิเนียม | ความสะท้อนและลายขัด |
| MAT_PLASTIC_Dark | พลาสติกคอมพิวเตอร์ | ผิวเม็ดละเอียด ความด้านต่างจากยาง |
| MAT_RUBBER_Cable | ยางสาย/ล้อ | ความด้านและรอยใช้เล็กน้อย |
| MAT_FABRIC_Office | เก้าอี้/ฉากกั้น | ลายทอและตะเข็บตามระยะที่เห็น |
| MAT_PAPER_Labels | เอกสาร/แฟ้ม/กล่อง | ตัวอักษรอ่านได้และไม่เบลอ |

ชื่อข้างต้นใช้กับวัสดุใหม่หรือ mapping ที่อนุมัติแล้ว ไม่ rename วัสดุ/วัตถุทั้งฉากทันที

## Texture และ UV

- แยก Base Color, Roughness, Normal และ Metallic ตามความจำเป็น ไม่สร้าง map ว่างให้ครบทุกช่อง
- สี Base Color ใช้ sRGB; ข้อมูล Roughness/Metallic/Normal ใช้ Non-Color
- วาง UV ตามลักษณะงาน: อาคารใช้วัสดุปูซ้ำ; ฉลาก/อุปกรณ์เฉพาะใช้ UV จัดตำแหน่ง; ไม่ Smart UV ทั้งแมพแบบเหมารวม
- Normal map ช่วยรายละเอียดผิวแต่ไม่เปลี่ยนเงารอบนอก เช่นใบไม้ มือจับ หรือรูปทรงเบาะที่ผิดต้องแก้ geometry
- เริ่มทดลองภาพ 1K สำหรับวัสดุทั่วไป/ชุด atlas และ 2K เฉพาะชิ้นที่มองใกล้หรือวัสดุร่วมที่จำเป็น ไม่ใช้ 4K ทุกชิ้น
- ตัวเลขความละเอียดเป็นจุดเริ่มทดสอบ ไม่ใช่สเปคตายตัว ลด/เพิ่มตามภาพที่เห็นในเกมและหน่วยความจำ
- Texture ใหม่ใช้ `T_<family>_<variant>_<BaseColor|Roughness|Normal|Metallic>_<resolution>.png`
- วัสดุ Procedural ต้องทดสอบส่งออกและ Bake ส่วนที่ส่งผ่านไม่ได้ ห้ามถือว่าสวยใน Blender แล้ว Godot จะเหมือนกัน
- บันทึกแหล่งที่มาและสิทธิ์ใช้งานทุก Texture ภายนอก ก่อนนำเข้าร่วมโปรเจกต์

## กฎรักษางานเดิม

- ไม่ย้าย scale/origin/pivot หรือ Apply Transform กับชิ้นส่วนที่ระบบเกมอ้างอิงโดยไม่ตรวจผล
- เก็บชื่อหน้าจอ ชื่อชิ้นส่วนประตู custom properties และ hierarchy ตาม `godot_contracts.json`
- ไม่รวม meshes ที่ต้องกดหรือเคลื่อนไหวกับเฟอร์นิเจอร์นิ่ง
- ก่อนแก้ shared Mesh/Material ดูรายการผู้ใช้งานก่อนเสมอ เพราะอาจเปลี่ยนหลายห้องพร้อมกัน
- เรนเดอร์ก่อน–หลังด้วยกล้อง/แสงเดียวกัน แล้วตรวจใน Godot เป็นระยะ
- ปรับแสงจริงใน Godot หลังนำเข้า ไม่ Bake เงาแรงถาวรลง Base Color

## ประตูตรวจรับก่อนขยายงาน

Phase 1 ต้องผ่านภาพตัวอย่างจากผู้ใช้ก่อนทำทั้งแมพ; UV ไม่ยืดผิดสัดส่วน; ผิววัสดุแยกไม้/เหล็ก/พลาสติกได้;
ไม่มีวัสดุหายหลัง export; จุดกดใช้งานยังตรง; การเพิ่มภาระต้องวัด ไม่อนุมานจากภาพเรนเดอร์
